## Rationale

The prior run was healthy on the macro signals (43% acceptance, every named production exercised, real depth spread up to 33701) so the changes here are targeted refinements rather than a rewrite: (1) the depth histogram had a hard gap between d4 and d500 -- nothing in the 5-499 range -- so a new isolated mid-depth (10-400) array/inline-table probe was added to fill exactly that gap, since that is the region where a C parser might show resource problems distinct from both trivial recursion and outright stack overflow. (2) All three found crash signatures are stack-overflow variants of the already-documented unbounded-recursion bug (array nesting, inline-table nesting, and an unreproduced flaky one likely from the same family), so per the 'steer away from already-found crashes' guidance the combined weight of the extreme deep-stress modes was cut from 20% to 10%, freeing sampling budget for parts of the grammar that have not produced a crash. (3) Since acceptance (43%) has headroom before risking pure-tokenizer-reject territory, the near-valid-malformed density inside normal_document was roughly doubled (denominator 60->30) and three new malformed-but-plausible shapes were added (bare-comma array, trailing-comma inline table, unterminated string) to broaden coverage of the reject path without duplicating the already-confirmed duplicate-key/table cases. (4) String generation got a new low-frequency 'malformed escape' arm (\\x) to keep the already-confirmed agreement case (tomlc99 rejects invalid escapes, matching the grammar) exercised, and the control-byte sample set was widened from 4 to 8 raw C0 bytes to broaden the byte-level string leniency probe the adaptation notes flag as worth attention. All grammar productions were already reached, so no new production names were introduced -- only more of the underexercised depth range and reject-path variety.

## Changes from the previous iteration

- Added a dedicated mid-depth (10-400) array/inline-table stress path (mid_array_value/mid_inline_table_value/mid_stress_document) because the reported depth_histogram jumped straight from d4:34 to d500:15 with nothing in between -- that 5-499 gap was empty and is now sampled directly.
- Cut the extreme deep-stress mode weight from 20% (8+7+5) to 10% (4+4+2) in toml_document_strategy because unique_crash_signatures=3 shows the array-nesting and inline-table-nesting stack overflows are already confirmed; per guidance this budget is redirected rather than re-finding the same bug.
- Raised the near-valid-malformed density in normal_document from 1-in-60 to 1-in-30 and added three new malformed shapes (bare-comma array, trailing-comma inline table, unterminated basic string) because acceptance_rate=43.0% was flagged healthy with room to push further into the reject path without risking tokenizer-only rejection.
- Added a low-frequency 'basic_invalid_escape' (\\x..) arm to string_value to keep the already-confirmed agreement case (malformed escape correctly rejected) exercised alongside the existing accepted-superset string edge cases.
- Widened CONTROL_BYTES from 4 to 8 raw C0 control bytes since productions_exercised showed 'string' already firing but the ADAPTATIONS notes flag raw control-byte leniency in basic strings as an under-tested byte-level area worth broadening, not just the original 4 sampled bytes.
